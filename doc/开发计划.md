## 1. 平台与硬件（已确认）

| 项 | 决策 |
| --- | --- |
| 模组 | **ESP32-S3-WROOM-1-N16R8**（16MB Flash / 8MB Octal PSRAM） |
| 框架 | ESP-IDF v5.x（建议 5.3+），目标芯片 `esp32s3` |
| 主架构 | **事件驱动**，基于 ESP-IDF 内置 `esp_event`（无需额外组件） |
| 屏幕 | 3.5 寸 ST7365 320×480，4 线 SPI（硬件 SPI + DMA），硬件横屏 480×320 |
| 输入 | 6 键按键（上/下/左/右/确认/返回）—— 后续阶段 |
| GUI | 当前不使用；LVGL 版本待定（倾向高版本 9.x） |
| 存储 | **无 OTA**；单 APP + ~12MB `storage` 分区（图片资源放内部 Flash） |
| 无线 | 本期不需要（架构预留） |

## 2. 事件框架（骨架）

- 事件基（`main/app_events.h`）：`INPUT_EVENT` / `DEVICE_EVENT` / `APP_EVENT` / `UI_EVENT`
- 分层：drivers → app 状态机 → comms(后续) / ui(后续 LVGL)；模块只收发事件，不直接调用
- 任务规划：
  - 事件循环任务栈默认 4096（handler 必须短小：只 post 事件 / 加锁写 UI / 置标志）
  - 后续 LVGL 渲染任务 ~8192；按键扫描 ~2048~4096；后续 Modbus ~4096
  - 开 `CONFIG_FREERTOS_CHECK_STACKOVERFLOW=2` + overflow hook；大栈可放 PSRAM

### ⚠️ 通用移植守则（每个页面移植必查 —— 退出/返回路径最容易踩坑）

> 来源：坑 6.8（菜单切页 task_wdt 死锁）+ 坑 B2-4（评估页"返回按钮确定" use-after-free 崩溃重启）。
> **退出/返回是每个页面都有的路径**，以下守则适用于 B3~B5 及所有后续页面移植，移植完成后逐条对照。

1. **切页销毁前，先把本页注册进 keypad group 的对象移出 group**
   - 原因：`Page_Clean()` 删除"焦点对象"时，LVGL `lv_group_refocus` 会向剩余对象发 `LV_EVENT_FOCUSED`，
     若回调去操作正在销毁/已删除的对象 → `lv_obj_invalidate` 死循环（task_wdt）或 use-after-free 崩溃。
   - 做法：入口函数（如 `Ass_LeaveGroup()`/`Menu_LeaveGroup()`）在 `Page_Clean()` **之前** `lv_group_remove_obj(...)`。
2. **`lv_group_remove_obj` 前必须 `lv_obj_is_valid()` 防护**
   - 原因：上一页被 `Page_Clean` 后，全局 widget 里的按钮/图片指针仍指向已释放内存（未置 NULL），
     在"返回"路径调用清理函数时 use-after-free（坑 B2-4：评估页返回按钮确定即崩溃重启）。
   - 做法：`if (lv_obj_is_valid(ptr)) lv_group_remove_obj(ptr);`（`lv_obj_is_valid` 只比较指针不解析，对悬垂安全）。
3. **定时器生命周期与页面一致**
   - 页面销毁/退出前：`lv_timer_del` 页面定时器并置 NULL（勿只 `pause`，pause 会留下悬垂的 user_data 对象指针）。
   - 定时器回调内避免访问可能已删除的对象（如 chart / label）。
4. **事件回调里引用"其他页"的控件时，用 `lv_obj_is_valid` 门控或只在页面激活时处理**
   - 例：`BackToMenu_Event_cb` 的 FOCUSED 分支引用 Page1 按钮（进入 Page4/5 后已悬垂）→ 先判 `lv_obj_is_valid(Ass_Widget.Ass_Btn)`。
5. **统一退出函数**（如 `Ass_BackToMenu()`）：停定时器 + 移出 group + 返回菜单，集中清理避免遗漏。
