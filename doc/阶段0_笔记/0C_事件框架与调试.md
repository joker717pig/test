# 阶段 0.C 事件框架 + 调试设施 — 笔记（0.6~0.7）

> 事件框架与 USB-Serial-JTAG 调试的坑。属于阶段 0 硬件笔记系列。

## 已验证结论
- 事件框架：`esp_event_loop_create_default()` + `app_events.h`（4 事件基 INPUT/DEVICE/APP/UI + 事件 ID + 测试 handler）
- 调试设施：`app_log.h`（统一 LOG 封装）、`app_debug.c`（栈溢出 hook + 栈水位任务）、`app_console.c`（help/info/mem/psram/stack/part/lcd 命令）
- monitor 验证：4 测试事件 + 任务栈水位打印

## 坑（重要，USB-Serial-JTAG console 输入）
1. **console 走 VFS 时 stdin 是非阻塞**：无数据 `read` 返回 0 / `getchar` 返回 EOF → `fgets/getchar` 会把命令拆成碎片并刷屏。
2. **直接调 `usb_serial_jtag_read_bytes()` 会崩溃**（LoadProhibited @0x4）：VFS console 未安装驱动句柄（`p_usb_serial_jtag_obj==NULL`），不能直接用该驱动 API。
3. **正确做法**：VFS `read(0, &c, 1)` 逐字符读，`<=0` 时 `vTaskDelay(20ms)` 继续等待（区分无数据与 EOF，避免忙等/刷屏），累积到 `\n`/`\r` 再执行命令。
4. **依赖坑**：`idf_component_register` 写显式 `REQUIRES` 会替换默认 requirements，common 组件由构建系统 `link_libraries()` 无条件注入，但**非 common 组件必须显式列出**（见 `0D` 笔记坑 4）。
