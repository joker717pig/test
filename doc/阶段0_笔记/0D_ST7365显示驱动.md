# 阶段 0.D ST7365 显示驱动 — 硬件笔记（0.8~0.11）

> **最重要的硬件笔记**：12P 接线、初始化序列、字节序、DMA 缓冲坑。属于阶段 0 硬件笔记系列。

## 1. 12P 屏接线（已确认，来源 sEMG-V1.4 原理图 WIFI1 模块）

| 12P 脚 | 信号 | ESP32-S3 GPIO | 说明 |
|---|---|---|---|
| 1 | GND | - | |
| 2 | RESET | **IO21** | 复位（低有效） |
| 3 | SDA/MOSI | **IO11** | SPI2_D 数据出 |
| 4 | SCL/SCK | **IO12** | SPI2_CLK 时钟 |
| 5 | CS | **IO10** | SPI2_CS0 |
| 6 | DC | **IO9** | SPI2_HD（命令/数据） |
| 7 | TE | IO14（未用） | 撕裂同步，0.D 不接 |
| 8 | SDO/MISO | IO13（未用） | SPI2_Q 读回，只写不读 |
| 9 | LCD_VCC | - 常开 | 屏供电，上电即有 |
| 10 | LEDA | →LCD_VCC | 背光阳极 |
| 11 | LEDK | - | 背光阴极，经 AW36402 驱动 |
| 12 | GND | - | |

- 背光亮度 **LED_PWM = IO3**（AW36402 亮度控制；0.D 先 GPIO 拉高常亮）
- **SPI 主机 = SPI2(FSPI)**，引脚正好是 FSPI 默认映射（SCK=12/MOSI=11/MISO=13/CS=10/HD=9/WP=14）
- **枚举值注意**：`SPI2_HOST = 1`、`SPI3_HOST = 2`（Kconfig 别写反）


## 3. 坐标映射（重要）
- MADCTL=0xE8 硬件横屏后，`draw_bitmap` 逻辑坐标：**x(0..479)→CASET, y(0..319)→RASET**（与旧工程 lv_port flush 一致，已验证）
- 分辨率宏：`LCD_H_RES=480, LCD_V_RES=320`

## 4. 坑（重要）
1. **RGB565 字节序 = MSB first（大端）**：主机是 little-endian，`uint16_t` 内存里低字节在前，但面板要高字节在前。`draw_bitmap` 内把主机序 uint16 **逐像素转大端**再送 SPI（否则红/蓝互换、花屏）。
2. **`esp_lcd_panel_io_tx_color()` 是异步的**（DMA 后台传输）→ 复用静态缓冲必须等上次传输完成。当前设计：**4 块环形交换缓冲 + `trans_queue_depth=4`** 形成流水线（CPU 转字节序 与 DMA 传输重叠），环形安全性靠 esp_lcd 按 FIFO 回收事务（队列满时 `get_trans_result` 等最旧事务 DMA 完成才复用槽位；DMA 按序完成，故写 `buf[i%4]` 时其上次 DMA 必已结束，**跨 draw_bitmap 调用同理**）。
   - ⚠️ `draw_bitmap` 结尾**不要**发 NOP polling 排空（早期版本有，已删）：那会让 LVGL 任务每帧多一次总线阻塞、拖慢帧率（见坑 #8）。flush 完成靠 SPI 中断 `on_color_trans_done → lv_disp_flush_ready` 异步通知，draw_bitmap 常态只排队、不阻塞。**但注意：OTA 擦写内部 flash 前必须做一次"统一排空 + 停渲染"静默 LCD，否则会冻死——那是另一回事，真根因与修复见坑 #9（不是这个每帧 NOP）。**
3. **初始化时 TE 已使能但 0.D 不接 TE 引脚**（只写不读，TE/SDO 均未初始化）；`lcd_cmd_bits=8, lcd_param_bits=8`。
4. **CMakeLists 依赖坑**：写 `REQUIRES` 会替换默认 requirements；common 由构建系统无条件注入，但**非 common 组件必须显式列出**：
   ```cmake
   REQUIRES "esp_lcd" "esp_driver_spi" "esp_driver_gpio"
            "spi_flash" "esp_psram" "esp_event" "esp_partition"
   ```
   （否则 `esp_flash.h` 找不到）
5. **宏参数逗号坑**：函数式宏 `TX_PARAM(io,cmd,param,size)` 传 `(uint8_t[]){0x02,0xE0}` 时，`(uint8_t[])` 括号先闭合，`{}` 内逗号会被当参数分隔 → 必须写双重括号 `((uint8_t[]){0x02,0E0})`。
6. **SPI 时钟 = 80MHz（定档 2026-08-07）**：ESP32-S3 SPI2 上限 80MHz，实测稳定、无花屏。ST7365 手册虽标 ~50MHz，但 80MHz 目检正常。若个别屏体质差可降 60/50MHz（`sdkconfig.defaults` 的 `CONFIG_LCD_SPI_CLK_HZ`）。
7. **依赖坑补充**：`bench` 用到 `esp_timer`（`esp_timer.h`），非 common 组件，**必须**加进 CMakeLists 的 `REQUIRES`，否则编译报 `esp_timer.h: No such file`。
8. **快速填充 vs 通用 draw_bitmap**：`app_lcd_fill` 走专用快路径（一次设窗 + 预构建大端带 + 连续流式 + 结尾单次排空；仅上电清屏用、不在 LVGL/OTA 路径，保留排空无妨）；`draw_bitmap` 为通用路径（LVGL 用），按带转大端 + 流水线、**纯异步不排空**（见坑 #9）。**不要把 fill 写成逐带调用 draw_bitmap**——逐带等待会毁掉流水线（实测 51ms/帧 vs 33.5ms/帧）。
9. **⚠️⚠️ OTA 擦写内部 flash 时 LCD 永久冻死——真根因是"SPI 完成中断/回调非 IRAM，撞上关 cache 窗口"，必须擦写前静默 LCD（2026-09-04 真机踩坑，当日复测推翻旧结论；现象/排查见 `doc/阶段D_笔记/0Y_OTA界面联调分步实施.md`）**：
   - 现象：OTA 升级后端三目标（STM32/图片/ESP32）日志全部成功，但屏上进度条停在中途（典型 stm32 100% / 图片 0~22% / esp32 0）再不刷新，像 UI 卡死；重启显示又正常。**卡死点 = 图片升级整片擦除 storage_b(~6MB) 开始的时刻**。
   - **旧结论（已证伪）**：一度以为是 `draw_bitmap` 结尾的 NOP polling 排空逼 LVGL 任务每帧阻塞等 DMA 所致，删掉排空即可。**真机复测：删了排空仍冻死**，故那不是根因。
   - **真根因（逐层核 IDF v5.5.3 源码确认）**：擦写内部 flash 每次都进 `spi_flash_disable_interrupts_caches_and_other_cpu()`——**关 cache、屏蔽所有非 IRAM 中断、停住另一核**。而 LCD flush 完成链路在该窗口里是断的：
     1. `app_lcd_init` 的 `spi_bus_config_t.intr_flags = 0`（**没加 `ESP_INTR_FLAG_IRAM`**）→ LCD 的 SPI 中断在关 cache 时被屏蔽（SPI ISR 用 `bus_cfg.intr_flags` 注册，见 `spi_master.c` `esp_intr_alloc(... intr_flags | ESP_INTR_FLAG_INTRDISABLED ...)`）。
     2. flush 完成回调链**全部不在 IRAM**：`spi_post_trans`(ISR, 有 `SPI_MASTER_ISR_ATTR`) → `lcd_spi_post_trans_color_cb`（esp_lcd，**无 IRAM_ATTR**）→ `lvgl_port_flush_io_ready_callback`（esp_lvgl_port，**无 IRAM_ATTR**，`LVGL_PORT_IRAM` 仅在 `CONFIG_LCD_RGB_ISR_IRAM_SAFE` 时才是 IRAM_ATTR，SPI 面板没开）→ `lv_disp_flush_ready`。
     3. **SPI LCD 没有 IRAM 安全 Kconfig**（`esp_lcd/Kconfig` 只有 `LCD_RGB_ISR_IRAM_SAFE` / DSI 选项，无 SPI）。
     4. esp_lvgl_port 对 SPI 面板**不在 flush_cb 末尾调 `lv_disp_flush_ready`，全靠 `on_color_trans_done` 中断回调**（`esp_lvgl_port_disp.c`：仅 RGB/DSI direct/full_refresh 才在末尾 ready）。
     - 于是关 cache 窗口里若有一带颜色 DMA 刚完成，其 trans_done 中断被屏蔽、完成回调（在 flash 里）无法执行；窗口结束后中断/回调与 SPI 驱动"中断惰性使能"状态机（`spi_bus_lock_bg_entry` 那段 disable/enable 竞态注释）错位，**flush_ready 永久丢失 → LVGL 认为 flush 没结束 → 整帧刷新永久冻死**。
   - **为什么不能走 IRAM 路线**：即便给中断加 `ESP_INTR_FLAG_IRAM`，ISR 在关 cache 时仍会调用放在 flash 的 `lcd_spi_post_trans_color_cb` / `lvgl_port_flush_io_ready_callback` → 取指即崩。要全链路 IRAM 必须改 IDF + managed 组件（不可改），故不可行。
   - **正解（已实现，2026-09-04）**：**擦写内部 flash 前，先静默 LCD，保证关 cache 窗口里没有任何在途 flush/DMA**：
     - `app_lcd_drain()`（`app_lcd.c`）：发一次 polling NOP。esp_lcd 的 `tx_param` 会先 `spi_device_get_trans_result` **回收所有在途排队事务**（等每条 DMA 完成、且 ISR 已跑 post_cb → on_color_trans_done → flush_ready）再发命令 → 返回时总线空闲、无 DMA 在飞、本帧 flush 通知已投递。
     - `app_lvgl_begin_flash_op()` / `app_lvgl_end_flash_op()`（`app_lvgl.c`）：begin 先 `lvgl_port_lock(0)`（递归锁，portMAX_DELAY；持锁后 LVGL 任务阻塞在取锁上、不再调 `lv_timer_handler`/发新 flush），再 `app_lcd_drain()`；end 释放锁恢复渲染。
     - OTA 三条擦写路径全部包裹（`app_ota.c`）：**图片**（整片擦 storage_b + 流式写 + NVS 切槽）、**ESP32**（`esp_ota_begin` 擦槽 + `esp_ota_write` + `set_boot_partition` 写 otadata）、**STM32 下载落盘段**（`fwrite` 到 SPIFFS，内部 flash；UART 拉块段 40~100% 不碰 flash，不包，进度动画照常）。每条返回路径（含失败）都 `end_flash_op()`。
     - 期间屏幕**保持最后一帧静态**（进度条不动），写完恢复。这是 SPI LCD + flash OTA 的标准做法（RGB 面板靠 IRAM-safe ISR + vsync 重启，SPI 无此机制，只能静默）。
   - 教训：
     - **SPI LCD 的 flush 完成依赖"非 IRAM 中断 + 非 IRAM 回调"，任何擦写内部 flash 的代码段都必须在其前后静默 LCD（停渲染 + 排空 DMA）**，不能假设 DMA 异步就安全。
     - `draw_bitmap` 结尾**不要**加 NOP 排空（那会让 LVGL 任务每帧多一次总线阻塞、拖慢帧率，见坑 #8），但**擦 flash 前的统一 drain 是另一回事、必须有**——两者不矛盾：前者是每帧常态、后者是擦写前的一次性屏障。
     - `app_lcd_fill`（上电清屏专用）保留它自己的 NOP 排空无妨（不在 LVGL/OTA 并发路径）。

## 6. 性能（定档 80MHz，2026-08-07）

| 配置 | 整屏填充 | 帧率 | 备注 |
|---|---|---|---|
| 40MHz + 单缓冲同步 | ~61ms（理论） | ~16fps | 初始未优化 |
| 80MHz + 流水线但逐带排空 | 51.2ms | ~19.5fps | fill 逐带调 draw_bitmap |
